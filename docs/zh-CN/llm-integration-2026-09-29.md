# LLM 怎么融进这条流程：位置、契约、闸门、实验

写于 2026-09-29。前提是 [research-2026-09-29-puredocbench.md](research-2026-09-29-puredocbench.md) 的两个结论：
（1）PureDocBench 的"仿真"来自 LLM 一次性写整页，代价是内容层黑箱、无真实感度量、真值靠 LLM 辅助抽；
（2）Synthetic Hospital 把 LLM 限制在叙事，标签先于叙事由程序导出，并用"换模型重渲染、排名不变"证明生成器不偏向某个模型。
本仓目前**一个模型调用都不在数据产出链路上**（见 README 的隐私契约与 `harness/llm_panel.py` 的干跑设计）。这份文档回答：
LLM 放在哪里能提高生成数据的质量、每个位置的契约与闸门是什么、哪些位置**永远不放**、以及这些位置对论文贡献什么。

> **修订记录**：当晚读了 MITRE 的 Synthea-LLM 论文（Kramer 等，arXiv:2507.21123 / JAMIA Open 2026）并再查了九篇相关工作之后，
> 方案有一处实质改动——新增 **L0：知识档案 → 队列 spec**，把它排到第一位——以及三处机制补强（渐进式修正、评审方差先测后用、刺激—响应检验）。
> 改动的理由与证据见 §7；§1、§5 已按修订后的写。
>
> **一句话原则**：LLM 只在**真值之后、闸门之前**工作，只改"说法与样子"，不改"谁、什么时候、什么值"；
> 它的每一个输出都当作**不可信文本**过同一套闸门（临床、可读性、隐私、保真），并且换一个模型重跑，评测排名必须不变。

## 0. 先回答"要不要"

| 顾虑 | 回答 |
|---|---|
| 会不会破坏"可重放、同 seed 逐字节一致" | 不会，只要 LLM 的产出是**离线的资源**（像 `scripts/build_*.py` 的产物一样入库、带溯源），生成器本身仍是"资源 + 代码 + seed"的确定性函数。在线调用只允许出现在评测侧 |
| 会不会破坏隐私论证 | 送出去的只有合成内容（`assert_synthetic` 已有）；风险在**回来的**文本：模型可能背出真实报告的句子。所以 LLM 文本**不得**进 `_vocabulary_fields` 豁免名单，必须以"不可信文本"身份过回放检测与 PII 谓词；命中即拒 |
| 会不会让语料偏向某个模型 | Synthetic Hospital 附录 C.2 的做法：同一真值换模型重渲染，被评系统的排名 Spearman ρ ≥ 0.8 才算通过。这是硬实验，不是声明 |
| 值得不值得 | 值得，但不是在值层。审查里"太干净、太简单、模板化"的评价，一半来自版式趋同、一半来自叙述句式有限；两者都是 LLM 擅长而规则不擅长的，而且都不碰真值 |

## 1. 五个位置（按价值排序）

对照 [research-2026-09-29-puredocbench.md §14](research-2026-09-29-puredocbench.md) 的流程 v2 七阶段，LLM 出现在阶段 0、2、5、6，**不出现在阶段 1（值层）与阶段 3（劣化层）**。

| # | 位置 | 阶段 | 在线/离线 | 改什么 | 不改什么 | 闸门 |
|---|---|---|---|---|---|---|
| L1 | **机构模板**：按家族属性生成整页 HTML/CSS 模板，表格与键值对是**槽位**，内容由渲染器注入 | 2.1 | 离线（构建资源） | 页面样子：页眉横幅、印章位、栏数、表格边框、字体、配色、构件顺序 | 表格里的每一个格子、印刷真值、语义真值 | 渲染成功 + `audit.readability` 0 丢失 + `audit.fidelity` 指纹落在真实分布内 + 隐私闸门 |
| L2 | **叙述改写**：具名所见描述、总检建议、门诊病史、日记句子的**模板级**同义改写 | 0.2（资源） | 离线 | 句式、连接词、语序、口语化程度 | 槽位（`{side}`、`{mm}`、`{items}`）、数字、单位、诊断表面、ICPC-3 表面 | 契约校验（§2）+ 隐私闸门（不豁免）+ 生成器鲁棒性实验（§4） |
| L3 | **候选提议**：从公开来源提名"目录里还缺什么"——指标别名、机构方言、套餐构成、所见的常见措辞 | 0.2 | 离线 | 只产生**候选**，写进资源前由程序判定（LOINC 解析器、出处可引用检查、n≥3 规则）或由人核 | 任何已入库的值 | 与 Synthetic Hospital 的 ICD/SNOMED 级联同构：LLM 提候选，程序判定，未通过的标记 unverified 不入库 |
| L4 | **评测面板**：多模型交叉标注（已有 `llm-panel`）、记录层盲评的预筛、失败簇的归因摘要 | 5、6 | 在线 | 不改语料 | — | 报一致性（σ、κ），不作闸门 |
| L5 | **属性标注助手**：视觉家族聚类后，对每簇的接触表给出属性候选，人复核 | 0.4 | 在线（有语料的机器） | 标注效率 | 真值 | 双标 + κ；LLM 只看**合成**接触表，或在本机跑开源 VLM——真实页面不出机 |

**不放的位置**（每条对应 [research-2026-09-29-puredocbench.md §8.4](research-2026-09-29-puredocbench.md) 的一个坑）：

* **不生成值**：值来自参考区间 × 个体基线 × 事件 × 噪声 × 恒等式；LLM 写值单页自洽（那篇 §2.3 实测过），但纵向、人群、跨源都不自洽，且不可审计。
* **不生成整页内容**：PureDocBench 的做法；内容层会变成黑箱，真值要靠抽取而不是编译。
* **不当标注器**：印刷真值由渲染数据结构编译、`readability` 核对；语义真值先于渲染。
* **不当闸门**：`llm_panel` 的文档已经说清：说不清标准的东西不能决定语料能不能用。

## 2. L2 叙述改写的契约（第一段落地）

这是最小、最安全、马上能做的一段，也是"生成器鲁棒性"实验的前提。

### 2.1 为什么是模板级而不是实例级

实例级（对每份文件的每句话现场改写）有三个问题：每次生成都要调模型，可重放性没了；同一个人两年的所见描述会无缘无故换风格；隐私闸门要对每一次生成的文本重跑回放检测。
模板级（对 `narratives.json` / `complaints.json` 里的每条模板离线生成若干**同义模板**，槽位原样保留）没有这些问题：改写一次、入库、过闸，生成器从"原模板 + 同义模板"里按 seed 抽。

### 2.2 请求

每条请求带：

| 字段 | 含义 |
|---|---|
| `id` | `findings.thyroid_nodule.finding.zh` 这样的资源路径 |
| `lang` | `zh` / `en` |
| `template` | 原模板，含 `{slot}` |
| `slots` | 槽位名与允许值（来自 `_placeholders`；数值槽只给类型） |
| `register` | 体裁：`ultrasound_finding` / `impression` / `advice` / `diary` / `chief_complaint` / `hpi` |
| `n` | 要几条 |
| `constraints` | 见 2.3，原样写进提示词 |

提示词是资源的一部分（`resources/llm_prompts.json`，hand-authored），版本化；PureDocBench 没公开提示词是它被诟病的一点，我们反过来做。

### 2.3 契约校验（程序，`mirobody_gen/llm/contract.py`）

候选文本必须**全部**满足，否则整条丢弃并记原因：

1. **槽位集合相同**：`{slot}` 名字与出现次数与原模板一致，不多不少，没有残留大括号。
2. **不引入数字**：候选里的数字串集合 ⊆ 原模板里的数字串集合（模板里的 "3–6 个月" 允许保留，不允许变成 "2–4 个月"）。
3. **锁定词原样在**：诊断表面、检查名、方向词（"升高/降低"、"左/右" 之外的槽位已单独保护）、单位符号。锁定词由资源路径决定：`impression`/`summary`/`surface` 类模板整句锁定（这些是 mirobody 要编码的表面，不改写）。
4. **语言与文字**：`zh` 候选必须含 CJK 且不含拉丁句子，`en` 反之；繁简不混。
5. **长度**：0.6–1.6 倍原模板（防止"扩写成一段科普"）。
6. **不含机构名、人名、编号形状**：复用隐私闸门的 PII 谓词与虚构池检查。
7. **去重**：与原模板及其它候选的归一化编辑距离 ≥ 0.15，否则不算新说法。

通过的候选写进 `resources/paraphrases.json`，`_source: "llm-paraphrase"`，`_provenance` 记模型、提示词版本、请求哈希、日期；**`_vocabulary_fields: []`**——这份文件的每个字符串都要过回放检测。

### 2.4 生成器接线

`book._fill` / `journal` 取模板的地方改为 `spec.phrasings(path, lang)`：返回 `[原模板] + 同义模板`，按文档 rng 抽。机构层面粘住风格（同一家机构的同一类所见每年同一说法），这与 `NORMAL_DIALECTS` 的处理一致。
不装 `paraphrases.json` 时行为与现在完全相同——LLM 层是可选叠加，不是依赖。

### 2.5 这一段今天落地了什么

* `mirobody_gen/llm/contract.py`：请求与候选的数据结构、`check()` 的七条规则、`slot_names()`。
* `mirobody_gen/llm/cache.py`：按 `sha256(model + prompt)` 的内容寻址缓存（Synthetic Hospital 的做法，每次调用可追溯）。
* `mirobody_gen/llm/paraphrase.py` + `mirobody-gen paraphrase`：从资源收集模板 → `--dry-run` 写请求包（不外发）→ `--apply responses.jsonl` 校验并写资源 → `--write`。调用模型的部分复用 `harness/llm_panel.py`，本机没有密钥时只能干跑。
* `tests/test_llm_contract.py`：七条规则各有正反例；干跑产物的形状。
* **没有**接线到生成器（2.4）：先跑一批候选、看通过率与隐私闸门的命中率，再决定抽样权重。这一步需要模型密钥，本机没有。

## 3. L1 机构模板：怎么借 PureDocBench 的长处而不背它的短处

PureDocBench 证明了"LLM 写 HTML/CSS → 浏览器渲染 → 从同一份源出真值"这条路能出像样的页面。我们只借前半段，把"内容"换成槽位：

```
家族属性（来自阶段 0.4 的标注：栏数、表格样式、页眉横幅、印章、单位位置、参考值方言……）
   │
   ▼  L1：LLM 写一份**带槽位**的机构模板（HTML/CSS + 槽位清单），例如 {{institution}}、{{subject_table}}、{{lab_tables}}、{{summary}}
   │
   ▼  校验：槽位齐全 → PyMuPDF Story 能排 → 塞一份已知文档渲染 → readability 0 丢失 → fingerprint 落在该家族属性内 → 隐私闸门（模板里不许有任何具体机构名/人名/地址；这些都是槽位）
   │
   ▼  入库：resources/templates_html/<family>.html，_source: "llm-template"，记模型与提示词版本；生成器按机构粘住模板
```

与现状的关系：`render/pdf.py` 现在是一套固定 CSS + 几个 HTML 片段函数，版式差异全靠列组、表头、方言这些**符号**参数。符号层保证的是"表格里怎么写"，L1 补的是"页面长什么样"——正是视觉家族（阶段 0.3）能测出来而符号指纹测不出来的那部分。
两层的分工要写死：**符号参数仍由 `layout.py` 抽，模板只决定容器**；否则又是两套真值来源（那篇 §13 问题 4）。

风险与对策：
* Story 排版能力有限（不认 CSS 宽度、跨页丢内容的教训）：提示词里给出允许的 HTML/CSS 子集，校验时逐块排版（现有 `_flow_verified`）。
* 模型写出的模板趋同（PureDocBench 的样页"整齐得像教科书"）：按家族属性**条件**生成，且用 `fidelity --visual` 的覆盖测试拒绝落在真实簇之外或全挤在一个簇里的模板。
* 隐私：模板只能含槽位与通用词；隐私闸门对模板文件全扫。

## 4. 实验：LLM 层对论文贡献什么

| 实验 | 问题 | 做法 | 通过标准 |
|---|---|---|---|
| E9 生成器鲁棒性（Synthetic Hospital C.2 式） | 语料是否偏向改写/模板所用的模型 | 同一 sealed seed 的真值，分别用模型 A、B 的改写资源与模板资源渲染两套语料；mirobody 与公开模型面板各跑一遍 | 被评系统的排名 Spearman ρ ≥ 0.8；主指标 |Δ| ≤ 0.05 |
| E10 说法多样性的代价 | 同义改写让抽取/编码变难多少 | 对照对：`base`（原模板）vs `view:paraphrase`（同义模板），语义真值不变 | 报配对差；这是"陷阱因果效应"（E3）在叙述层的延伸 |
| E11 版式多样性的代价 | LLM 模板 vs 固定模板 | 同上，`view:template:<family>` | 报配对差 + 视觉覆盖率 |
| E1 补充 | 加了 L1/L2 之后真实感是否真的上去了 | 指纹种数比、视觉覆盖、记录层盲评（阶段 6.2） | 盲评准确率向 50% 靠近，且 E9 通过 |

写进论文的方式：LLM 不是贡献本身，**"LLM 只改表面 + 程序真值 + 鲁棒性实验"**这个组合是贡献的一部分——它同时回应了 PureDocBench（内容黑箱）与 Synthetic Hospital（没有文档层）各自的短板。相关工作里把 L1 对齐到 PureDocBench/WeVisDoc 的"语义 HTML 双编译"，把 L2 与 E9 对齐到 Synthetic Hospital 的"标签先于叙事 + 换模型重渲染"。

## 7. 读 MITRE Synthea-LLM 与再调研之后：方案改了什么

### 7.1 那篇论文讲了什么（Kramer, Mathur, Adams, Walonoski；MITRE；arXiv:2507.21123，JAMIA Open 9(1) ooaf123，2026）

| 项 | 内容 |
|---|---|
| 目标 | 用 LLM 辅助写 Synthea 的疾病模块（JSON 状态机） |
| 四阶段 | (1) **疾病档案**：LLM 结合人选的权威来源（StatPearls、JAMA 综述、学会指南）写出 30–60 条**编号、带出处**的陈述（患病率、分组发病率、症状概率、检查、治疗、随访、并发症）；医生审阅后手工修正——尤其是定量数字；(2) 从档案生成模块，**每个状态必须引用它实现的档案条目号**（可追溯）；(3) 两级验证：Level 1 程序检查（路径完整、每个 Encounter 配 EncounterEnd、转移概率合 100%……），Level 2 用 LLM 逐条给档案条目打分 0/0.25/0.5/0.75/1 并写理由；Level 3 人群级验证**没做**（Synthea 跑一次太慢）；(4) **渐进式修正**：把得分最低的 ≤10 条连同理由与建议喂回模型，随机打乱顺序，反复 10 轮 |
| 评审可靠性（表 1） | 三个模块 × 三个评审模型 × 5 次：Claude 3.5 Sonnet 标准差 1.5–5.3，GPT-4o 8.3–18.4，Gemini 1.5 Pro 4.7–7.8——**评审模型之间的差异大过被评对象之间的差异**；他们选方差最小的当评审，且评审与生成在独立会话 |
| 结果 | 初版模块 Level 2 分 GPT 37.9 / Claude 64.4 / Gemini 83.1；10 轮后 Claude、Gemini 接近 100，GPT 停在 65。Synthea 专家复核：可运行但不到生产质量；**两个模型都持续幻觉医学编码** |
| 自述局限 | 编码幻觉；模块孤立、无共病；无人群级验证；每次 20–30 分钟、全项目 <500 美元；仍需临床专家；提示词缺**负面规则**（出现了持续数月的门诊）；状态数随迭代膨胀（72 → 109） |
| 附录 | 全部提示词公开（A.1–A.4）；两版疾病档案（仅凭模型知识的 36 条 vs 加了三个来源后的 45 条） |

### 7.2 它改变了我的方案什么

**A. 新增 L0：知识档案 → 队列 spec。这是最大的改动。**

原方案把"值层不放 LLM"理解成"LLM 不碰值层"。读完这篇才看清：LLM 不该碰的是**值**，可以碰的是**值层知识的草稿**。
本仓队列引擎的原型、干预剧本、随机事件（8 / 6 / 5 条）全是手写的，这是"更高质量生成数据"真正的瓶颈——
共病、用药对化验的效应、随访模式、老年与女性特有的轨迹，靠手写扩不动；而 MITRE 的档案机制正是为这个设计的。

搬过来是这样：

```
公开指南文本（我们指定，只给公开来源）
   │
   ▼  mirobody-gen profile <condition>：LLM 起草"病况档案"——编号陈述 + 每条的出处标签 + 类别
      （患病率与分组、受影响指标与效应幅度/起效天数/半衰期、随访间隔与医嘱、典型所见、用药与其化验效应）
   │
   ▼  人核（定量数字逐条核，MITRE 的经验：定量最容易错）
   │
   ▼  build_cohort.py 读档案，编译成原型/剧本/事件条目；每个条目带 requirements: ["HT-3", "HT-17"]
   │
   ▼  三级验证（比 MITRE 多一级）
      L1 程序：spec 测试 + 临床审计（恒等式、边界、RCV、诊断—值互证）
      L2 评审：LLM 对着**生成人群的统计**（200 人跑一遍，秒级）逐条给档案条目打分——这是 MITRE 因为 Synthea 慢而没做的人群级验证
      L3 刺激—响应（Degli Esposti 2026 的"先校准仪器"）：档案写 ALT ×2，生成队列里 ALT 中位数必须落在 ×2 的容差内；这是确定性检查，不是 LLM 判断
   │
   ▼  渐进式修正作用于**档案**（不是代码）：最低分条目连同理由回给模型，随机顺序，≤10 条一批
```

与 MITRE 的三点不同，都是刻意的：LLM 的产出不是可运行的东西，是经人核的档案，编译由确定性脚本做；
编码一律不从模型来（LOINC 走本仓解析器，ICPC-3/SNOMED 走 mirobody 的词表，解析不出的标 unverified 不入库——Synthetic Hospital 的级联）；
人群级验证是主验证而非缺项。

这一条排到第一位，因为它是唯一能增加**内容**丰富度的 LLM 用法；L1、L2 增加的是表面多样性。

**B. 渐进式修正进 L2（已实现）与 L1。** 契约的拒绝理由本来就是一行一条、机器可读，正好回喂：`mirobody-gen paraphrase --refine 1`
把被拒候选连理由送回一轮，只要还缺的条数。L1 模板同理：渲染失败、可读性丢失、指纹越界的原因回喂。

**C. 评审模型先测方差再用。** 写成协议：3 个固定对象 × 5 次 × 每个候选评审模型，报标准差，选最小的；评审与生成不同会话。
`harness/llm_panel.py` 的设计已引用这张表，现在把它作为 L4 与"改写自然度评审"的准入条件。

**D. 负面规则与膨胀上限。** 提示词明确写"不做什么"（L2 已有）；档案条目 ≤ 60、每模板同义说法 ≤ 5、每家族模板 ≤ 3，防止 MITRE 观察到的"越迭代越复杂"。

### 7.3 再调研：其他工作各自给了什么证据

| 工作 | 结论 | 对方案的影响 |
|---|---|---|
| Liu 等 2026（百万级 MIMIC 病历 LLM 改写的系统评测，arXiv:2605.17775） | 改写保住粗粒度信息与预测效用，**丢细粒度**（ICD 编码掉分）；错误以语境误读、时间混乱、测量值错、编造为主；**按块改写**少丢但语境不全 | 直接支持"模板级 + 锁定词 + 不动数字"的契约；给 E10 一个可检验的预期（编码损失应接近零） |
| Poulett 等 2026（纵向合成病历流水线，arXiv:2606.26879） | 结构化患者 → 病程 → LLM 写病历，LLM 校验与增补；70 患者 × 20–50 份 | 叙事层邻居；无文件/图像层。相关工作里放"值层/叙事层" |
| Lin 等 2025（商用 LLM 直接生成病历，arXiv:2504.14657） | 特征少时可用，**维度上去分布与相关性就失真**（83 维时 KL 明显上升） | "LLM 不写值"的定量依据 |
| Patient-Zero 2025（arXiv:2509.11078） | 从指南做分层属性置换生成患者，医生盲判分不出、临床质量更高 | 同样"知识而非真实记录"的来源，与 L0 同构；它让 LLM 渲染全部内容，我们只让它改表面 |
| olmOCR 2 2025（arXiv:2510.19817） | 合成 HTML 文档 + 从源码抽二元**单元测试**当 RL 奖励 | L1 模板必须附带单元测试（槽位在、块顺序、表格格值）；本仓可读性审计就是这类测试，要显式化成"每模板一组测试" |
| OmniDocLayout 2025 / RIDGE 2025 | LLM 能生成多样版式（百万级版式数据训练的 0.5B 模型胜过通用 LLM）；关系丰富的文档生成 | L1 可行；提示我们**通用 LLM 直接写版式会趋同**（PureDocBench 的样页问题），要按家族属性条件生成并用视觉覆盖测试拒绝趋同 |
| Bevin 等 2025（真实票据保版式换内容） | OCR + LLM 换内容 + 修补重绘，真值自动对齐 | 方向与我们相反：真实件不能进链路。它在合成侧的对应物是对齐视图 |
| Degli Esposti 2026（校准仪器） | 合成人群先做**内部效度**：对已知方向的刺激是否有序、可复现地响应，再谈像不像真的 | 变成 L0 的第三级验证与 E3 的框架；写进 paper.md 效度威胁第 13 条 |
| Synthetic Hospital（前文 §12） | 标签先于叙事；换模型重渲染排名不变 | E9 不变 |

### 7.4 不变的判断，以及为什么证据更强了

* **LLM 不写值**：Lin 等的维度失真 + Synthetic Hospital 化验 LOINC 只 28.9% + MITRE 的编码幻觉，三处独立证据。
* **LLM 不写整页**：PureDocBench 的黑箱代价不变；olmOCR 2 说明"源编译 + 单元测试"才是可验证的路。
* **LLM 不当标注器、不当闸门**：MITRE 表 1 的评审方差就是理由——评审之间的差异比对象之间的差异大。
* **一切模型产出是不可信文本**：隐私闸门第 6 条不变。

### 7.5 对论文的影响

* 贡献表述不变（"LLM 只改表面 + 程序真值 + 鲁棒性实验"），加一句：**知识层也可以由 LLM 起草、由程序编译、由人群统计验证**——这是 MITRE 想做而 Synthea 做不到的 Level 3，本仓因为生成秒级而能做。
* 相关工作 §7.1、§7.5 各加了一段（paper.md 已改），效度威胁加了第 12（模型偏向）、13（内部效度）条，实验加了 E9–E11。
* 文献库新增 9 条，作者与日期经 arXiv API 核对。

### 8.1 跑了什么

```bash
# .env 里放 OPENROUTER_API_KEY；LLM_API_KEY 可以直接写成 OPENROUTER_API_KEY（客户端会解析引用）
# 注意端点是 https://openrouter.ai/api/v1（.env 里若写成 api.openrouter.ai 会连不上）
mirobody-gen paraphrase --models openai/gpt-6-luna --n 3 --refine 1 --workers 8 --write
mirobody-gen audit-privacy --targets mirobody_gen/resources
mirobody-gen build --seed 7 --people 6 --out out/c6_base --render --pairs 2 --no-paraphrase
mirobody-gen build --seed 7 --people 6 --out out/c6_llm  --render --pairs 2
mirobody-gen compare out/c6_base out/c6_llm
```

|---|---|
| 模板 | 237 条（中 120 / 英 117）：所见描述 38、科室条目 40、正常所见 31、建议 100、日记 19、主诉 9 |
| 模型调用 | 410 次（每条一轮 + 需要时一轮修正；8 路并发约 3 分钟；串行时每次约 20 s，跑不完） |

### 8.2 对比：同 seed、6 人、两次构建

真值层逐字节相同（manifest、语义读数、印刷行三个哈希一致）；三道审计在带改写的语料上全部 0 问题。

| 叙述层 | 句数 | 不同句数（无 → 有） | 字符 TTR | distinct-2 | 有改写时与无改写不同的句子比例 |
|---|---|---|---|---|---|
| 总检建议 | 159 | 89 → 98 | 0.073 → 0.083 | 0.166 → 0.204 | 75.5% |
| 日记 | 173 | 164 → 169 | 0.131 → 0.140 | 0.323 → 0.358 | 72.8% |
| 科室条目（异常） | 40 | 23 → 24 | 0.275 → 0.274 | 0.412 → 0.391 | 45.8% |
| 超声/影像描述 | 200 | 99 → 106 | 0.075 → 0.080 | 0.160 → 0.188 | 22.6% |
| 主诉 | 3 | 3 → 3 | — | — | 0% |
| 印象/诊断（锁定，不改写） | 167 | 50 → 50 | 同 | 同 | 0%（应为 0） |

怎么读这张表：
* "不同的句子比例"才是改写层的直接效果——建议与日记七成以上换了说法；超声描述只有两成，因为**同一机构粘住一种说法**（设计如此：一家的 LIS/超声工作站只有一份字典），6 个人只落在几家机构里。人数上去，机构数上去，这一列会涨。
* 不同句数与 TTR 的涨幅小，是同一个原因：粘性把多样性放在"机构之间"而不是"句子之间"。这与真实语料"四分之三版式只出现一次"的形状是一致的方向。
* 印象/诊断一行必须是 0——它是 mirobody 要编码的表面，锁定寄存器不进改写。

### 8.3 看到的问题

* **契约管不到语义的搭配**：日记模板 "{s}{dur}了，明天去看医生" 被改成 "这阵子{s}{dur}了……"，槽位填进 "1年" 就成了"这阵子膝盖疼1年了"。槽位保住了，搭配没保住。两条对策：改写请求里把槽位的**取值范围**给全（现在数值槽只标 `<number>`，时长槽应给 "3天…1年" 的全表）；对接受的候选做一次 L4 式自然度评审（不作闸门，只排序给人看）。
* "与原模板太近"占拒绝的 74%：模型倾向于最小改动，修正一轮后仍如此。可以把去重阈值 0.15 写进提示词，或要求"换句式而不是换词"。
* 回放筛丢掉的 68 条全是英文套话，说明对英文而言参考集的 12 字窗口偏严（英文 12 个字母只有两三个词）。规则先不改：宁可少几条英文建议，也不给模型文本开口子；等 E10 的数据再定是否把英文窗口放宽到词级。
