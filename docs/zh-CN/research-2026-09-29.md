## 1. tietai-synthea（PySynthea）1.4.1：我们的 issue 修了什么、没修什么

issue #113（[docs/issues/pysynthea-observation-fidelity.md](issues/pysynthea-observation-fidelity.md)，2026-09-23 提，
2026-09-25 以 PR #114 关闭）。1.4.1 的 CHANGELOG 说：`reference_ranges.json` 按 LOINC 给区间（含性别/年龄变体），
`interpretation` 由区间推出（只有 H/L/N，所以标记与区间不可能矛盾），红细胞指数改为"独立：HGB、MCV、MCHC；派生：HCT、RBC、MCH"，
球蛋白 = 总蛋白 − 白蛋白，白细胞分类按比例归到 100。

**实测**（`pip install tietai-synthea==1.4.1`；`synthea -p 8 --seed 7`；`python3 -m harness.synthea_check <output/fhir>`）：

| 项 | 1.4.0（issue 里的数） | 1.4.1（本次） |
|---|---|---|
| 带 referenceRange 的 Observation | 0 / 2323 | **1020 / 2175**（36 个 LOINC 里 14 个有区间） |
| 带 interpretation | 0 | 1020（N 781 · L 169 · H 70） |
| 标记与区间矛盾 | — | **0 / 1020** |
| 红细胞面板 MCV / MCH / MCHC 不自洽 | 6–7 / 8 | **0 / 8** |
| 值带超过 3 位小数 | 有 | **仍有 63 / 1858**（集中在 6690-2 WBC、718-7 HGB、777-3 PLT、32207-3 PDW 等血常规码） |
| 主诉 | — | 349 份就诊记录里 281 份"No complaints."，其余是诊断名（"viral sinusitis (disorder)"），不是症状 |

**结论与动作**：

1. 我们在 issue 里承诺的校验器已经兑现：`harness/synthea_check.py`（只读 FHIR bundle，不依赖本仓生成器，
   查覆盖、标记-区间一致、红细胞恒等式、蛋白与分类、印刷精度；`--strict` 非零退出）。可以作为回复贴回 #113，
   顺带指出第 3 条（精度）还在。
2. **不把 PySynthea 接成种子层**（PLAN §3.2 曾计划用 ESL-Bench 或 PySynthea 的虚拟人）。理由：它的主诉是诊断名而不是
   症状，locale 包目前只有 us，值的精度还没修；而我们自己的队列引擎已经有诊断（SNOMED，`spec/cohort.json`）、
   事件时间线、按机理取值。接缝仍留着（`generator/manifest.py` 的 conditions 注释），等它有 zh locale 与症状级主诉再评估。
3. 它 1.3.0 的临床笔记模板（`templates/notes/note.md.j2`：Chief Complaint / HPI / Social History / Allergies / Medications /
   Vital Signs / Assessment and Plan）是英文门诊笔记的合理骨架，我们的英文门诊病历（`build_outpatient`）参照了它的分段。

## 2. mirobody 上游（2026-09-22 → 09-29 的变化）与本仓的对齐

读的是同组织 mirobody 仓库当天的工作分支（最后一次提交 2026-09-29）。

### 2.1 主诉：ICPC-3 症状轴

| mirobody 的契约 | 本仓的对应 |
|---|---|
| 两个独立码集：S 轴 331 码（症状/主诉）、D 轴 887 码（诊断）；`resolve_symptom` / `resolve_condition` 各自**精确匹配**一个短语（`symptoms_zh.tsv` 403 行、`conditions_zh.tsv` 293 行……），整句要走 `/journal/sentence` 先由模型拆 | `spec/complaints.json`：51 个症状条目，每个中文表面**逐条对照 symptoms_zh.tsv 抄下**，带那边的 S 码；另有 7 个刻意不在词表里的"前沿"表面（多尿、面色苍白、泡沫尿……），期望结果写明 `no-match` / `refused`（疼）/ `needs-input`（打嗝） |
| 结果三态：`coded / needs-input / refused`，原因 `icpc3:no-match / ambiguous / too-broad` | 每条主诉真值带 `icpc3` 与 `expect` |
| `POST /journal/sentence` 拆句：`kind ∈ measurement/symptom/condition/medication/other`，保留原话，`150/95` 拆成两个读数，`发烧38.5` 是一个症状加一个体温读数 | `journal.jsonl`：387 条（8 人冒烟）→ 每条一句口语（"早上起来肩膀疼，压力大。"、"最近5天总是睡不着，量了血压135/85。"），`expected` 列出该拆出的症状（表面 + S 码 + 期望结果）与测量值（键 + LOINC） |
| 诊断轴：高血压 KD73、2型糖尿病 TD72、高脂血症 TD75、缺铁性贫血 BD66、甲减 TD69、慢性肾病 UD66、脂肪肝 DD81、上呼吸道感染 RD02；`糖尿病`/`贫血` 是 `!ambiguous` | 门诊病历的诊断行只印词表里**有**的表面；体检所见的诊断表面（`spec/narratives.json` 的 `findings[].surface`）也逐条对照过：脂肪肝/胆结石/肾结石/乳腺增生/前列腺增生/子宫肌瘤/静脉曲张/痔疮/脊柱侧弯/颈椎病/结膜炎/近视/骨质疏松有码，甲状腺结节/肝囊肿/胆囊息肉/肾囊肿/肺结节/颈动脉斑块/龋齿/牙结石/幽门螺杆菌等**没有**——那正是考弃权的素材，与检验层刻意留的 9 个解析不出的指标同一用意 |
| `benchmarks/health_records/cases.json`：`{lang, kind, name, code, outcome, reason, series}` | 我们的真值字段可以一行映射过去（`text→name`，`icpc3→code`，`expect→outcome`） |

### 2.2 基因：消费级导出文件

| mirobody 的契约 | 本仓的对应 |
|---|---|
| 识别 WeGene / 23andMe / AncestryDNA / MyHeritage / FamilyTreeDNA 的横幅与列名，VCF 4.x；无表头的按调用行形状识别并**拒收**（不送模型） | `generator/genomics.py` 按 `spec/genomics.json` 的 `vendors` 出 WeGene / 23andMe / AncestryDNA / MyHeritage / VCF 五种格式，表头照真实格式（build 37/38 声明在横幅里） |
| 位点表 489 个 SNV（dbSNP b155 common ∩ CPIC v1.60），41 个带基因标注（CYP2C19/2C9/2B6/3A5/4F2、DPYD、NAT2、NUDT15、SLCO1B1、TPMT、UGT1A1、VKORC1）；表外的落 `unresolved`，`--` 落 `no_call` | 每份文件：41 个 PGx 位点 + 位点表里其余 448 个的随机子集（120–260 个）+ 8 个表外常见位点（ALDH2、MTHFR、APOE ×2、MCM6、FTO、HFE、HERC2）+ 1.5% 无调用。基因型按手写的东亚/欧洲等位基因频率做 HWE 抽样（只求像人） |
| 真值字段 `canonical.json`：`rsid/chrom/pos37/pos38/ref/alt/gene/array_gt/vcf_gt/call_status/zygosity` | `genomics.jsonl` 同名字段，另加 `genotype_raw`、`in_catalog`、`n_off_catalog`、`n_no_call` |
| `th_pgx_result` 没有任何代码写它；`array_coverage` 一律 `not_determined` | 所以本仓**不**产出星号等位/表型真值（那是 mirobody 明确不做的判定），只在 spec 的 `label` 里注明常见星号等位作注释 |

隐私：没有任何真实基因型进入生成路径，坐标是公开 dbSNP 记录，频率是手写近似——结构上不可能泄露真人基因组。

### 2.3 设备：手机健康库批量接口

| mirobody 的契约 | 本仓的对应 |
|---|---|
| `POST /api/data`，`{"records":[{indicator, value, unit, time, source}]}` ≤500 条；`source` 是厂商标识（apple_health/huawei/xiaomi/health_connect…），`indicator` 是厂商字段名，经 `res/crosswalks/<vendor>.tsv` 编到 LOINC；一个字段对两个码的（华为 blood_pressure）不猜，要按目录指标名送 | `generator/devices.py`：按人抽厂商（中文 华为 45 / 苹果 30 / 小米 20 / Health Connect 5），字段名照抄 crosswalk；血压按目录名 `systolicPressures`/`diastolicPressures`。每人若干 `devices/<pid>/<vendor>_batchNN.json`（≤500 条，可直接 POST）+ `devices.jsonl` 真值（每条的 LOINC） |
| 两源一码：`Body weight` 与 `bodyMass` 同为 29463-7 | 体重秤序列来自 `physiology.weight_at`，与体检报告上的体重是同一条线；家用血压计的值来自 `physiology.measure`，与门诊病历的血压同源 |

8 人冒烟：12,965 条记录；60 人约十万条。

### 2.4 抽取契约与文档类型

抽取契约没变（`original_indicator/value/unit/reference_range/detection_method/status/notes`，文档级 `content_info` 与
`additional_info{content_summary, assessment, recommendations, ...}`），影像/病理走 `KIND_FINDING`。新的对应：

* 科室键值对与辅助检查叙述 → `blocks[].items`（`detection_method = Physiological / Imaging`）；
* 总检结论与建议 → `summary`（对应 `additional_info.assessment / recommendations`），逐条标明来自哪条所见或哪组异常指标；
* 门诊病历的主诉/诊断 → `complaints` / `diagnoses`。

**仍未接上的**：mirobody 的 `tests/e2e/harness.py` 与 `tests/e2e_real_reports.py`（都被 gitignore，只在本机）默认仍指向
一个本机的、不随仓库分发的用例目录；仓库里没有任何地方提到 mirobody-gen 或 `MIROBODY_SYNTH_CORPUS`。
PLAN §6 的接线是下一步，而且只能从 mirobody 侧开 PR。

## 3. 体检报告合理性审查

对着 `out/p2`（09-23 的产物）逐份看，问题分三类：

| 问题 | 为什么不真 | 改法（已落地） |
|---|---|---|
| 体检报告只有检验表格：一般检查 + 血常规 + 肝功能 + …，没有内科/外科/眼科/耳鼻喉/口腔，没有心电图、B 超、胸片，没有总检结论与建议，没有封面 | 真实体检报告书（真实语料最大的一类，157/627）三分之二是科室键值对与叙述；63/76 份有科室部分 | `generator/book.py`：封面 → 阅读说明 → 总检（六成机构印在前，四成印在后）→ 一般检查 → 内科/外科/眼科/耳鼻喉/口腔/妇科（键值对，2 列或 4 列）→ 辅助检查（心电图带条图、胸片/CT、腹部/甲状腺/颈动脉/乳腺/前列腺/妇科超声、骨密度、碳13）→ 检验表格 → 签名与印章 |
| 一般检查印"呼吸 17 次/分" | 呼吸频率是病房与门诊的生命体征，体检的一般检查印身高/体重/BMI/腰围/血压/脉搏 | `vitals` 医嘱去掉 `resp`；新增 `vitals_clinic`（T/P/R/BP/体重）只用于门诊病历的体格检查行；新增指标 `temp` 体温 |
| 所有体检都印同一套 67 项：胱抑素 C、糖化白蛋白、载脂蛋白 A1/B、脂蛋白(a)、eGFR 全在 | 基础套餐不会有这些；糖化白蛋白连高端套餐也很少做 | 三档套餐（`spec/cohort.json` 的 `checkup_packages`）：基础 52 项、标准 73 项、深度 90 项；`ga` 只在内分泌门诊的扩展医嘱里 30% 出现；档次按人抽定，逐年 12% 概率升档 |
| 高血压复查产出一张"检验报告单"，上面印身高体重血压 | 血压是门诊测的，写在病历里，不会印成检验单 | 高血压复查全部走**门诊病历**（主诉/现病史/既往史/体格检查行/辅助检查/诊断/处理）；其它慢病复查四成走门诊（病历 + 化验单），六成只有化验单 |
| 心电图参数印成检验单一行一项 | 真实是心电图报告：条图 + 参数 + 诊断结论 | `build_ecg_report`：参数小表 + Ⅱ导联条图（按心率画的 P-QRS-T）+ 心律 + 诊断（窦性心律正常 / 窦缓 / 窦性心律不齐 / T 波改变 / 房早） |
| 没有影像报告 | 真实语料里 CT/放射/超声报告加起来几十份 | `build_ultrasound_report`（腹部超声：逐器官所见 + 提示 + 一半带扇形斑点图） |
| 英文报告也用 `≤7.00&ng/mL` 这种 `&` 粘连 | `&` 粘连是国产 LIS 导出的方言 | 未改——这一条要在 `layout.py` 的 `UNIT_AT` 按语言分权重，列入待办 |
| 总检没有 | 真实报告最有价值的一页 | `summary_block`：所见逐条 + 检验异常按组归纳（血脂/血糖/肝功/肾功/尿酸/血常规/贫血/甲功/肿瘤标志物/尿常规/血压/BMI）+ 逐组建议 + 结语；血红蛋白偏高**不**写成贫血（分方向） |
| 所见每年独立抽 | 囊肿结石结节不会自己消失 | `generator/profile.py`：黏性所见按人抽一次、带起始日期，尺寸每年长约半毫米；脂肪肝轻→中按年推进、生活方式干预后退回轻度 |

还看到但**没改**的：两个人名池（`fiction.json`）里的英文名是"中文姓 + 英文名"混搭（Wei Carter），对英文机构不算错；
体检报告的检验部分仍是一张张分表，真实里也有整页大表的，形态覆盖够。

## 4. 拟真度：从"太干净"到"像真的"

### 4.1 文档结构层（P4）

见 §3 表。新增文档种类：`checkup_book`（重做）、`outpatient_record`、`ecg_report`、`ultrasound_report`、`home_log`
（血压日记 / 晨起体重：一张表里 7–14 天，每行自己的日期——mirobody `resolve_report_date` "7 行进、1 行出"的规模化素材）。

### 4.2 图像层（P3，照 PureDocBench）

细节见 [degrade.md](degrade.md)。要点：24 个场景 = 4 个分层（T2 扫描、T3 手机拍纸、T4 劣化件、T6 屏幕），每个场景是
"纸张 → 印刷/复印 → 采集 → 数字处理"的算子链，强度 mild/moderate/severe；所有视图共用真值；参数对着真实语料 315 张图像的
聚合统计校准（`docs/numbers_images.json`：白底 51%、灰度 42%、JPEG 质量中位数 93、长边中位数 1262、几乎不歪、横版 45%）。
对照对里每个 base 另出 6 个对齐视图。

### 4.3 与 WeVisDoc 的关系

WeVisDoc 是一个训练框架，它的数据方法我们采了三条：语义 HTML 双编译（我们本来就是）、劣化按来源分家族、
"看不见的内容不保留原真值"（手指只压页边留白；严重档进 stress）。它的第二阶段（留出探针找失败簇、定向补数据）是训练侧的，
对评测侧的对应物是 `audit/readability.py --ocr`：按场景报告印刷真值被 OCR 认出的比例，哪个场景掉得多，就是提取管线要补的地方。

## 5. 广泛调研：拟真的多源健康档案怎么生成

按"给谁用"分四类。每一行写清能拿来什么、为什么没用。

### 5.1 结构化记录（虚拟人与时间线）

| 方案 | 给的 | 取舍 |
|---|---|---|
| Synthea / PySynthea（tietai-synthea） | 状态机疾病模块、SNOMED 诊断、FHIR R4、1.4.1 起带参考区间与标记 | 主诉是诊断名；只有 us locale；精度未修。种子层接缝留着不接 |
| ESL-Bench（本团队，arXiv:2604.02834） | 100 个合成用户、事件驱动的指标级联、五级难度问答 | 值由 LLM 生成、不受诊断约束（我们审计过）；它没有文件层——那正是本仓补的一环。共用虚拟人的消融（PLAN §6.1）仍是目标 |
| GAN/扩散类表格合成（综述 PMC12203555、arXiv:2309.12380） | 在真实 EHR 上拟合 | **不采纳**：Stadler（USENIX Sec 2022）证明在真实数据上拟合的合成器要么防不住推断攻击要么没效用；本仓的隐私论证是"真实记录不在取值路径上"，拟合会把它推翻 |
| Coogee 式审计（字段级/跨字段/时序） | 三层审计的分法 | 已是本仓 `audit/clinical.py` 的结构（恒等式、硬边界、人口学、标记、RCV、诊断-数值互证） |

### 5.2 文件层（版式与图像）

| 方案 | 给的 | 取舍 |
|---|---|---|
| MedRepBench（arXiv:2508.16674） | 真实报告图像的逐行客观标注、评分口径 | 已用作评分口径（`harness/score.py` V0 复现官方脚本） |
| PureDocBench / WeVisDoc | 对齐三视图、场景算子链、采集链路、评分公式 | 已采（degrade.md） |
| Augraphy | 53 个增强的目录 | 作为算子目录参考，用 PIL 自实现；可做 `--augraphy` 后端 |
| Genalog（Microsoft） | HTML → 渲染 → 劣化 → OCR 对齐标签 | 同构；劣化少，WeasyPrint 与本机字体耦合 |
| Doc3D / Inv3D / SyntheticDoc | 真实纸张几何与路径追踪渲染 | 作为可选 `warp_map` 升级 |
| SynDocDS / SSD-DIS | 物理光照下的多样阴影 | 软边多边形近似 |
| DocDjinn | VLM 版式 + 扩散手写 | 手写留作外部资产 |
| 扫描 App（扫描全能王/微信文档模式）、微信压缩规则 | 国内真实上传最常见的两条链路 | 已实现 `app_enhance`、`wechat_scale` |

### 5.3 主诉与日记

没有公开的"合成主诉"数据集能直接用（ChatMed 之类是真实问诊，mirobody 拿它做过 E0 评测）。本仓的做法是把症状池挂在
原型与事件上（糖尿病人开二甲双胍前口渴乏力、感冒两周咳嗽咽痛、加班一个月失眠颈痛），表面对照目标系统的词表——
真值因此是"该编成什么码 / 该弃权"而不是"像不像"。日记句子是模板拼的，够测拆句与编码，不够测语言多样性；要更像人，
可以在**固定真值**的前提下让 LLM 改写句子（真值不动，只换说法），这是下一步可选项。

## 8. schema 扩充：公开来源、加了什么、为什么这样加

用户的判断是对的：原目录（99 项指标、3 档套餐、11 项辅助检查）是从我们自己那批报告里蒸馏出来的，
覆盖的是**这批报告恰好有**的项目，不是**体检行业在印**的项目。这一节记录扩充时查的公开来源、
每个来源采了什么、以及有意没采的。

### 8.2 加了什么

* **指标 99 → 172**：乙肝五项 + 丙肝抗体、CA19-9/CA15-3/CA72-4/CYFRA21-1/NSE/SCC、游离 PSA 与比值、胃蛋白酶原 Ⅰ/Ⅱ 与比值、凝血四项 + INR + D-二聚体、ABO/Rh、尿微量白蛋白/UACR/β2-微球蛋白、超敏肌钙蛋白 I/NT-proBNP、胰岛素/C 肽/餐后 2 小时血糖、甲状腺球蛋白及抗体、RF/ASO/抗 CCP/IgG/IgA/IgM/C3/C4、淀粉酶/脂肪酶/胆碱酯酶/前白蛋白、非 HDL 胆固醇、便潜血、幽门螺杆菌抗体、肺功能 5 项、baPWV/ABI 4 项、人体成分 4 项、心脏超声 5 项、HPV16/18/其他高危 + TCT、血氧饱和度。
* **两种新的值类型**：`categorical`（血型，一个人一辈子一个值）；定性项加了人群阳性率与阳性写法——乙肝表面抗体 55% 阳性（接种过疫苗，阳性不算异常）、核心抗体 8%、表面抗原 6%、幽门螺杆菌抗体 40%、便潜血 4%、HPV 其他高危型 8%、TCT 6%（ASC-US 为主）。**抗体类按人抽一次**，不按每次就诊抽，否则同一个人每年的乙肝五项会来回翻转（烟测里核对过：10 人 102 次就诊，黏性项无一翻转）。
* **医嘱组 28 → 52，套餐 3 → 5**（入职、老年、基础、标准、深度）。深度套餐的检验部分从 14 组到 27 组。
* **辅助检查 11 → 17**：肺功能、动脉硬化、人体成分、心脏超声是**参数型**（`kind=params`）——一张小表 + 结论，读数计入印刷真值但不再进检验表；眼底照相、乳腺钼靶是叙述型。
* **科室 6 → 7**：中医体质辨识（平和质 / 气虚 / 痰湿 / 阳虚 / 湿热），痰湿质对脂肪肝、糖代谢原型加权。
* **具名所见 40 → 55**：阻塞性/限制性通气功能障碍、动脉弹性减退、踝臂指数减低、内脏脂肪超标、室间隔增厚、舒张功能减低、二/三尖瓣少量反流、视网膜动脉硬化、乳腺良性钙化（BI-RADS 2）、四种偏颇体质。前七种由数值触发（`condition`），与心动过缓同一机制。
* **总检两行新内容**：分级判定（A–E，按区域）与重要异常结果提示；真值里是 `kind=grade`（带 `area`、`grade`）与 `kind=critical`。
* **派生量与恒等式**：非 HDL = 总胆固醇 − HDL；f/t PSA；PGR = PGⅠ/PGⅡ；FEV1 = FVC × 一秒率。四条都进了临床审计的恒等式表。
* **版式**：`table.two_result_columns` 从"延后"变成活的陷阱类。

### 8.3 有意没加的

* HBV-DNA、肝纤维化四项、HCV-RNA：门诊专科项目，不在体检套餐里。
* 尿常规的比重/酸碱度之外的更多干化学项（胆红素、尿胆原、亚硝酸盐已有）：增加行数不增加难度。
* 胃肠镜、CT 冠脉钙化积分、头颅 MRI：叙述型报告的结构与超声不同（分段、活检、Kappa 评分），值得单独做一版而不是塞进 `imaging`。
* 骨密度 Z 值、眼压数值化：已有 T 值与眼压行，收益小。
