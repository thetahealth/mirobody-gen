## 1. 现状勘察（决定设计的事实，不是背景介绍）

### 1.1 形态知识从哪里来

本仓的版式与陷阱知识来自一个**不随仓库分发的参考集**（去标识的检验与体检文档及其版式分析）。
参考集与它的任何派生物都不在版本库里，也不进入生成路径；进入仓库的只有按 §4.2 的规则过闸后蒸馏出的**形态**
（列组、参考值方言模板、单位变体、标记方言、陷阱类名、聚合分布），每条带 `source` 标签。
早期的一轮聚合统计（`library/`）没有脱干净（含真人测值示例与仪器批号），因此它只能作为蒸馏来源，本体不入库。

有用的形态知识（这是真正的资产）：

- **版式空间**：76 份人工确认报告里 62 种不同版式；表格列组 33 种（最常见是最简两列
  `项目名称+检查结果` n=76，其次五列 `项目名称/结果/参考值/单位/标志` n=64）；参考值方言 9 种；
  单位风格 11 种（`/L` 与 `/l`、`fL` 与 `fl` **各占 50:50**）；科室呈现 63/76 是键值对。
- **文档规模分布**：见 NUMBERS.md。注意那里有**两个不同的量**：
  `每文档表格行数`（分析器看到的印刷行，p50=6）与 `每文档 readings`（旧产线提取出的条数，
  p50=9）。生成器按前者对齐，因为它对应"一份文件里印了多少行"。
- **文本来源构成**：`cache-ocr` 377 / `production-xlsx` 157 / `production-pdf` 86
  —— **六成语料走 OCR**，这是测试素材必须复现的比例。
- **hazards 目录**：`analysis/` 里每份文档都带一份提取陷阱描述（条数见 NUMBERS.md）。
  **这是全世界买不到的东西**：它是真实 OCR + 真实版式在这套管线上的失败模式清单。
  （`library/grammar.json` 里另有一个 2725 的数字，那是旧管线按另一种口径聚合的，
  与这里的条数没有换算关系。两个数字打架过一次，现在各归各的定义。）
- **指标分布**：541 个指标带单位方言、参考值方言、值形状（`9.9`/`C`/`<9.9` 这种形状码）、
  数值分位数、异常率。分位数与异常率可作为**校准目标**（不作为取值来源，见 §4.1）。

### 1.2 mirobody 那边需要什么

- `tests/e2e/harness.py:55` 与 `tests/e2e_real_reports.py:34` **硬编码了真实患者文件**：
  一个本机绝对路径下的 `cases` 目录，文件名形如 `<姓名>_体检报告_<日期>_<体检号>.pdf`
  ——姓名、日期、档案号全在文件名里。CLAUDE.md 把它写成了发版前必走的 owner 基线。
  （这里刻意只写形状不写实例：本文件在 git 白名单内，写一个真实文件名进来，
  就是把要防的东西亲手放进了开源仓库。这个错误在本文档的第一版里真的犯了，
  2026-09-22 的评审抓到，连同对象库里的两个旧版 blob 一起清除。）**这是这次要一并解决的隐私问题**：
  换成合成语料，基线才能进 CI、才能给别人跑。
- `tests/e2e_real_reports.py` 现在只能**报告**提取率（"the coded RATE is reported, not asserted"），
  因为真实文件没有真值。**有了 manifest 就能断言**——这是合成语料最大的增量。
- `demo/generate.py` 是"4 个文件 + 2 个人 + 手写常量"的规模，形态单一（全英文、无 OCR 路径、
  无多页、无 hazard）。它要留着（demo 的职责是走查，不是压测），我们做的是它的**上游压测版**。
- 现成可复用的资产：`mirobody/kernel/decoders/synthetic.py`（garmin/whoop/oura 的合成 payload，
  确定性、纯 stdlib）、`mirobody/testing/`（contracts / golden / phi_lint）、
  `mirobody/engine.resolve`（实测：51 个候选指标名 48 个能解析到 LOINC，
  未解析的 `尿葡萄糖`/`25-羟基维生素D`/`癌胚抗原` 本身就是好的 frontier 素材）。
- 提取行的字段契约（`prompts/file_indicator_extract.py`）：
  `original_indicator / value / unit / reference_range / detection_method / status / notes`。
  **manifest 的行字段必须与它一一对应**，否则评分要靠猜。

## 2. 外部调研：谁已经做过，我们抄什么、不抄什么

| 来源 | 给我们的东西 | 不采纳的部分 |
|---|---|---|
| **Synthea**（JAMIA 2018）+ Generic Module Framework | 疾病进展用**状态机 + 加权随机**编码，每个虚拟人走完整生命线 —— 我们的 `person/timeline` 直接采用这个形式 | 它的输出是 FHIR 结构化记录，没有"文件形态"这一层，而我们要测的恰恰是文件 |
| **ESL-Bench**（事件驱动的纵向合成健康 agent 基准，**本团队工作**，arXiv:2604.02834） | ①事件注入→指标级联响应；②**真值直接来自生成过程**，归因问题因此有可判定答案；③五级难度（direct/single_hop/multi_hop/multi_hop_temporal/attribution） | 它只到结构化数据层，**不产文件**——这一环正是本项目要补的，见 §6.1 与 §10 |
| **医学文档抽取基准**（medRxiv 2026，1000 份 mock 报告） | 三段式流水线（结构化真值 → 模板渲染 → 图像劣化）与我们的设计同构；**实测传真式劣化让平均 F1 掉 38.8%**，证明"劣化分层"是测得出东西的；部分匹配给半分的评分法 | 只有 7 个 LaTeX 模板（我们有 62 种实测版式）；单语种 |
| **DTBench**（文档转表格合成基准） | 难度轴要**正交可控**（表数量、列数、噪声、周边叙述文本密度），才能定位是哪一维打垮了提取 | — |
| **SynthDoG**（Donut/ECCV 2022） | 分层渲染（背景/纸张/文本/布局采样）的工程形式 | 它的目标是预训练造量，不追求版式保真 |
| **Augraphy**（MIT，35+ 像素级 + 8 空间级劣化，含 `Faxify`/`BadPhotoCopy`/`InkBleed`/`DirtyDrum`/`Folding`） | 直接用作 T3/T4 劣化层；它的三相流水线（ink / paper / post）就是我们要的架构 | 作为**可选**依赖，缺失时回退到自写 PIL 劣化（不能让语料生成依赖一个重依赖） |
| **Stadler et al., USENIX Security 2022《Synthetic Data – Anonymisation Groundhog Day》** | **最重要的一条**：对真实数据**拟合生成模型**再发布合成数据，要么防不住推断攻击、要么没有效用。→ 我们**不拟合**。见 §4 | — |
| **《The DCR Delusion》(2025)** | DCR / NNDR 这类距离型隐私指标会给出虚假的安心感 | 所以 DCR 只当 sanity check，不当论据 |
| **Coogee（统计保真 → 临床一致性审计）** | 审计要分三类：**字段级合理性 / 跨字段一致性 / 时序合理性**，还要查人口学冲突（男性做妊娠项目） | 它用 LLM 打 10 分制；我们用**确定性规则**，可重放、不花钱 |
| **Westgard / EFLM 生物学变异数据库** | 每个分析物的**个体内变异 CVI / 个体间变异 CVG** 实测值（已抓到 28 项：HbA1c CVI 1.9%、TG 19.9%、ALT 19.4%、Na 0.6%…） | — |
| **WS/T 404.1–.8 / WS/T 405**（中华人民共和国卫生行业标准，公开 PDF） | 中国成年人参考区间的**权威公开来源**（404.4 已下载解析核对：总胆红素 男≤26.0 女≤21.0 μmol/L。405 的血红蛋白是 男 130–175、女 115–150 g/L——第一版这里抄的是旧教材的 120–160/110–150，而那一格当时还标着『已验证』。检索摘要不等于核对过原文。） | — |
| **MCSCSet**（医学领域中文拼写纠错混淆集） | 中文 OCR 形近/音近混淆对，作为 hazard 注入的补充词表 | 我们**首选**本仓实测的 hazard 分类学；通用混淆集只作补位 |

**一句话结论**：这套东西在文献里的定位是 *knowledge-based（规则/机理驱动）合成*，
不是 *data-driven（模型拟合）合成*。Stadler 那篇批的是后者。选前者，隐私论证才站得住 —— 这不是
"我们做了脱敏"，而是**真实记录根本没有参与取值**。

## 3. 架构

```
真值层                      渲染层                    消费层
────────                    ────────                  ────────
spec/            ┐
 指标目录(公开)   │  person/   ─→ encounter/ ─→ layout/  ─→ render/  ─→ out/
 参考区间(WS/T)   ├→ 人设+纵向   每次就诊     从版式空间   7 种形态     文件
 生物学变异(CVI) │  状态机+事件  选套餐        采样一套     + 劣化分层   +
 版式空间(过闸)   │     │                                              manifest
 hazard 目录     ┘     └─→ physiology/ 由状态派生指标值 ─────────────→ (真值)
                             ↑ 恒等式约束（BMI/Friedewald/MCHC/…）
                                          │
                      audit/ ──────────────┴──── 两道独立闸门：隐私 + 临床
```

### 3.1 `spec/` —— 唯一被提交进 git 的"学来的东西"

每一条都带 `source` 标签，审计会检查标签存在：

- `public-standard`：WS/T 404.x / 405 参考区间、LOINC 编码、UCUM 单位、Westgard CVI/CVG。
- `format-token`：从 `library/` 蒸馏的**形态**（列组、参考值方言 `0-10&ng/ml` 的模板化形式、
  单位大小写变体、标记方言 `↑/H/偏高/+`、页面构件类型、日期标签词）。过闸规则见 §4.2。
- `hand-authored`：叙述模板（超声所见、CT 印象、体检小结）、虚构机构名池、虚构人名池。

### 3.2 `person/` —— 真值根

60 人，队列按患病率配比而非均匀采样（这样"异常率"这个可校准量才有意义）：

| 原型 | 人数 | 纵向剧本 |
|---|---:|---|
| 健康成人（含年轻/老年两端） | 18 | 只有生物学变异与季节项 |
| 糖尿病前期 → 2 型糖尿病 | 10 | HbA1c 缓升；事件：二甲双胍起始 → 3 个月后回落 |
| 血脂异常 + 他汀干预 | 8 | LDL 阶跃下降（起效延迟 4–6 周），TG 慢降 |
| 缺铁性贫血（女性为主） | 5 | HGB/MCV/MCHC 联动下降；补铁后网织红先升 |
| 甲状腺功能异常（甲减/甲亢/桥本） | 5 | TSH 与 FT3/FT4 反向耦合；左甲状腺素滴定 |
| CKD 2 → 3a 进展 | 4 | 肌酐缓升，eGFR 由 CKD-EPI 2021 计算而非采样 |
| 脂肪肝 / ALT 升高 → 生活方式干预 | 5 | ALT 高变异（CVI 19.4%）+ 减重事件 |
| 高血压治疗 | 5 | 收缩压阶跃 + 昼夜/白大衣效应 |

**优先复用 ESL-Bench 的虚拟人，而不是另造一批。** ESL-Bench（本团队工作，arXiv:2604.02834）
已有 100 个合成用户及其事件时间线。取其中 60 个、把同一条时间线渲染成文件，比另起炉灶多买到两样
东西：①两个基准可以做消融对照（见 §6.1）；②它们的事件模型已经过一轮论文审视。
上表的原型配比在那种情况下退化为**校验表**——用来检查取到的 60 人是否覆盖了这些疾病轨迹，
缺哪类就补造哪类，而不是全部自造。ESL-Bench 用户数据在 HuggingFace
（`healthmemoryarena/ESL-Bench`，按用户目录组织，含 `*_timeline.json`），P1 第一件事是把它拉下来
核对时间线 schema。

每人 2–5 年、3–12 次就诊。事件用（起效延迟、幅度、衰减）三元组建模，写进 manifest 的时间线 ——
**归因类问题的答案由此可计算**（"我的 LDL 为什么降了" 的真值 = 注入的他汀事件）。

### 3.3 `physiology/` —— 取值模型

一条读数 = `个体基线（CVG 抽样）× 个体内变异（CVI）× 分析变异（CVA）× 事件效应 × 状态修正（空腹/体位/季节）`，
然后按该指标的**实测有效数字规则**取整（`9.9` / `9` / `<9.9` 形状码来自 spec）。

**派生指标一律由恒等式算出，禁止采样**（这是临床一致性的主要来源，也是审计的抓手）：
BMI、LDL（Friedewald，TG>4.5 时改用直接法并在报告里标注）、MCV/MCH/MCHC（由 HGB/RBC/HCT 定义）、
球蛋白 = 总蛋白 − 白蛋白、A/G、间接胆红素 = 总 − 直接、eGFR（CKD-EPI 2021）、
中性/淋巴/单核绝对值 = WBC × 百分比、分类百分比合计 = 100。

### 3.4 `layout/` + `render/` —— 形态层

版式从 §3.1 的空间采样（列组、列序、参考值方言、标记方言、单位大小写、页眉页脚构件、
科室呈现形式、所见呈现形式），渲染前过一遍**格式契约**（合格报告必须有什么、顺序约束），
不通过就报错，不静默出片。

七种形态，按 §1.1 实测的 text_source 构成配比（OCR 路径 ~60%）：

| 层 | 形态 | 考什么 |
|---|---|---|
| T0 | 带文本层 PDF（单页/多页） | 基线：提取的上限 |
| T1 | XLSX / CSV（含**转置表**：指标在列、`一级/二级目录` 作行标签、自带中英对照） | 结构化路径、转置解析 |
| T2 | 扫描 PDF（无文本层，150–300 dpi，轻微倾斜） | 栅格化 + OCR 分支 |
| T3 | 手机拍照 JPG（旋转、透视、不均匀光照、反光、手指遮挡） | 视觉模型真实入口（占真实上传相当比例） |
| T4 | 劣化件（传真/复印、低对比、屏摄、90° 横放） | 鲁棒性；文献实测这一层能吃掉 ~39% F1 |
| T5 | 多页体检报告书（10+ 页，多科室，叙述 + 表格混排，p95=103 readings） | 长文档、分页、科室键值对 |
| T6 | PNG 截图（医院门户 / 设备屏） | 非纸张来源 |

每份文件按概率注入**具名 hazard**（密度见 NUMBERS.md，按实测分布抽），
hazard 名写进 manifest —— 这样"哪一类陷阱打垮了提取"是可查询的，不是猜的。

配套再出一份**设备时间序列**（复用 mirobody 自带的 `kernel/decoders/synthetic.py` 形状，
garmin/whoop/oura/apple），让同一个虚拟人在"文件"和"设备"两条源上都有数据 —— 这是 mirobody
的 `两源一码` 场景（`Body weight` 与 `bodyMasss` 同为 29463-7）唯一能规模化测试的方式。

### 3.5 `manifest` —— 真值

每份文件一条记录：文件 id / 人 id / 就诊日期 / 层级 / 格式 / 版式指纹 / 注入的 hazard 列表 /
文档类型 / 页数 / 语言，加上逐行真值（**字段与 mirobody 提取契约同名**：
`original_indicator, value, unit, reference_range, status, detection_method`），
外加评分用的附加列：`canonical_name, unit_ucum, loinc, value_kind, expect_resolvable`。
语料级另出：人物时间线（事件）、归因问答集、以及"本批语料的形态分布 vs 真实语料分布"对账表。

### 3.6 难度与多样性模型 —— "在合理范围内为难"的可操作定义

这是整套语料的**核心**：不出版式，就只是把 `demo/generate.py` 放大了 100 倍。
但"难"必须是可控、可归因、有上界的，否则测出来的数字不解释任何东西。

#### 3.6.1 真实语料的难度到底是多少（实测 627 份，不是估计）

数值一律见 [docs/NUMBERS.md](docs/NUMBERS.md)，这里只说它们意味着什么。

| 量 | 实测 | 含义 |
|---|---|---|
| 每份文档的提取陷阱条数 | 原始 p50=6/p95=10；**剔除不可复现的脱敏痕迹后 p50=4、p75=6、p95=8、max=14、零陷阱 9.3%** | 真实文档本来就很难。我最初写的"每份注入 0–3 个"低了。但也不能直接用原始的 6——`artifact.redaction_placeholder`（«NAME» 占位符）占了 33% 的文档，那是本语料自己的加工痕迹，不是真实现象，算进去会让注入密度系统性偏高。**生成器按 p50=4 / p95=8** |
| 版式指纹 | 627 份 → **513 种**，比例 **0.818** | 与旧 HANDOFF 在 76 份上量到的 0.82 一致，这个统计量是稳的 |
| 指纹重复形状 | 绝大多数指纹只出现 1 次，中间稀疏，然后两个大家族（份数见 NUMBERS.md）。**2026-09-23 改了指纹定义**（旧定义用分析器的描述文本，有措辞噪声），数字随之变化，见 `audit/fingerprint.py` | **重头 + 长尾**，不是均匀分布 |
| 列组 | **444 种**不同列组；最高频是最简两列 `项目名称+检查结果`，其次五列；**142 份根本没有表格**（纯叙述报告，占 22.6%） | 表格形态极度分散，且"报告≠大表格"。第一版这里写 46，那是"列头为空的表格数"，不是"没有表格的文档数" |
| 语言 | 多标签计数（归一后）：zh-Hans 568 / en 386 / zh-Hant 28 / ja 2 | 合计大于文档数，因为一份文档常同时带中英标签——**中英混排是常态**。归一前有 9 种写法，其中 4 种都是繁体 |

结论：**约四分之三的真实文档，其版式只出现过一次**（主定义下；只看列头时是 40%，见 NUMBERS.md 的敏感性一行）。 靠模板匹配的提取器在这里必死，
能泛化的才活得下来。所以我们的采样器不能是"62 个模板轮流用"，必须能造出长尾。

#### 3.6.2 "合理"的三条边界

难度只沿这三条边界推，越界的一律不进主榜单：

1. **可读性下界（硬约束）**：注入陷阱后，每一条真值行仍必须能被一个认真的人读出来。
   读不出来的行**不进召回的分母**——它转为"必须弃权"的行：提取器报告读不到即为正确，
   编造一个值即为错误。这条线把"难"和"不可能"分开。
   （依据 mirobody 自己 `eval/README.md` 的判断：弃权不是错误答案，错答才是。
   一条读不出来还要求答对的题，测的是幻觉倾向，不是提取能力——那要单独测，不能混进召回。）
2. **真实性上界（校准约束）**：每类陷阱的注入率 = 它在 627 份真实文档里的**实测率**；
   每份文档的陷阱条数从**实测分布**抽（见 NUMBERS.md 的"每文档陷阱密度"一行，
   注意那是**剔除脱敏痕迹之后**的密度），不是我拍的；
   共现只允许实测共现过的组合。这条挡住"造一个现实中不存在的怪物，然后宣布提取器失败"。
3. **可归因性（工程约束）**：每份文档注入了哪几条陷阱，写进 manifest。主榜单每份文档封顶在
   实测 p95（见 NUMBERS.md）；叠加超过 p95 的进独立的 `stress` 分层，
   **单独报告，永不并入主指标**。

#### 3.6.3 多样性的形状：机构 = 版式家族

要复现真实的指纹比例，不能去调一个"多样性参数"——那是旧教训第 5 条明令禁止的。
要复现的是**产生它的机制**：

- 建 ~25 个**虚构签发机构**，每个机构一套**粘性版式家族**（列组、列序、参考值方言、
  标记方言、单位大小写偏好、页眉页脚构件固定）；
- 其中 2 个是"大客户"，各占语料 5–8%（对应实测的两个大家族）；其余是长尾；
- 家族内允许小抖动：打印批次、页脚时间戳格式、某次换了纸、单位大小写漂移、多一列少一列；
- 于是指纹比例是这个机制的**产物**，不是拧出来的参数。如果生成出来偏离真实值，
  要改的是机构数与家族粘性，不是在采样器里加个系数。

这个机制还顺带买到一件事：同一个虚拟人几年内在同一家机构复查，会产生**同版式的多份报告**——
这正是 mirobody 要做纵向序列合并的真实场景。

#### 3.6.4 采样器的值域测试（可执行，不是感觉）

把版式分解为正交维度：`列组 × 列序 × 参考值方言 × 标记方言 × 单位大小写 × 页面构件 ×
表头层数 × 科室呈现 × 叙述呈现 × 语言混排`，各维从实测边缘分布抽，组合后过格式契约。

**测试**：实测的 513 种指纹，采样器必须每一种都造得出来。造不出的那些，说明维度分解缺了一维——
这是一个能跑的覆盖测试，而不是"看起来挺全的"。反向还要有约束：契约必须挡掉不可能的组合
（例如"有参考值列"与"参考值方言=无参考值"同时成立）。

#### 3.6.5 定向为难：打 mirobody 自己承认的失败模式

上面三条是**分布性**的难度。另加一批**定向**样本，每一个都对应 mirobody 文档里写明的已知坑，
且都有可判定的正确答案：

| 造什么 | 考什么 | 依据 |
|---|---|---|
| `中性粒细胞#` 与 `中性粒细胞%` 同时出现 | 同名不同单位 → 不同 LOINC（26499-4 / 26511-6） | `tests/e2e/harness.py` 的 `loinc_of` 注释 |
| 繁體 `血紅素` | 折叠成"血红素"会被答成 HbA1c 4548-4，而台湾"血紅素"=血红蛋白 | `eval/README.md` zh-hant 分层 |
| 同一分析物分别印 mmol/L 与 mg/dL | 14647-2 vs 2093-3，单位进身份 | `demo/README.md` |
| 一张表里 7 个早晨的体重 | `resolve_report_date` 给整份文件一个日期：7 行进、1 行出 | `demo/README.md` 实测 |
| 转置表（指标在列、`一级/二级目录` 作行标签、自带中英对照） | 转置解析 | 旧 HANDOFF 实测 |
| 血压印成一格 `120/80` | 必须拆成收缩压/舒张压两个指标 | 提取 prompt 第 6 条 |
| `阴性` / `++` 定性值 | 应落 `[Presence]` 码而非质量浓度码 | `eval/build_testset.py` qualitative 分层 |
| 结果列无单位、单位只在参考值行 | 单位丢失 | hazards 实测类 |
| `113mmHg` 值单位粘连、`0-10&ng/ml` 参考值单位用 `&` 粘连 | 实测**最高频的两类**陷阱（32 份 / 39 份文档） | hazards 实测类 |
| `fL`/`fl`、`/L`/`/l` | 实测各占 50:50，手写种子曾系统性偏向一侧 | 旧 HANDOFF |
| 已知无法解析的指标名（`尿葡萄糖`/`25-羟基维生素D`/`癌胚抗原`） | 考**弃权**而不是乱猜 | 本次实测 48/51 |

这就是"在合理范围内为难"的精确含义：**难点全部来自真实观察到的现象，每一个都有可判定的正确答案，
每一个都能在 manifest 里被点名。** 不做的是：随机 Unicode 垃圾、现实中不存在的字体、
以及把提示注入混进主榜单（那是安全测试，另开一个分层，不与提取能力混算）。

## 4. 隐私模型（这一节是整套方案的承重墙）

### 4.1 威胁模型与核心论证

四类风险，逐条对应控制：

| 风险 | 控制 |
|---|---|
| a. **逐字泄漏**：真实文本片段出现在生成物里 | 生成期不读 `corpus/` `rows/` `analysis/` `pipeline/`；审计做 n-gram 回放检测 |
| b. **统计泄漏**：真人取值分布可被反推 | **取值不来自语料**。参考区间来自 WS/T 公开标准，变异来自 Westgard 公开表，个体值由机理模型生成。语料分位数只用于**事后校准比对**，不进取值路径 |
| c. **spec 泄漏**：蒸馏出的形态里夹带罕见真实串 | 过闸：`n≥3 份文档` + 白名单形态正则 + 人工审阅落到带 `source` 标签的 spec 文件。`"RJ-QR-46-16"`（n=7 但是仪器编号形态）这类被形态白名单挡掉 |
| d. **误认**：合成文件日后被当成真实病历 | 默认可见水印 + 文件元数据标记（PDF `/Producer`、XLSX docProps、EXIF UserComment）+ manifest 的 `synthetic: true` |

**核心论证一句话**：真实记录在生成路径上**没有信息流**。这不是强度论证（"脱敏得很干净"），
是结构论证（"根本没连上"）。Stadler 那篇之所以成立，前提是生成模型在真实数据上拟合过；
我们没有这个前提。

### 4.2 形态过闸的具体规则

从 `library/` 取一项形态，必须同时满足：

1. `documents ≥ 3`（罕见串一律丢弃 —— 一次性出现的东西最可能是某台仪器、某个批号、某家机构）；
2. 命中形态白名单（单位 token、标点方言、已知标签词表、列头词表、日期格式），**不是**黑名单；
3. 落入 `spec/` 时改写成**模板**而非实例：`"0-10&ng/ml"` → `"{lo}-{hi}&{unit}"`；
4. 带 `source: format-token` 标签与一行注释说明它是从什么形态观察里来的。

`value_examples`、`snippets`、`wrong_results` 这些**字段整体不进 spec**（它们是真实测值与真实
片段）。hazard 只取 `class`（类名）与 `documents/occurrences`（计数），片段自己重新合成。

### 4.3 审计（独立实现，非零退出码）

沿用本仓最贵的一条教训 —— **审计不能调用过滤时用的同一个谓词，否则只可能确认过滤器自己的盲区**。
因此 `audit/` 与 `spec/`、`render/` 不共享任何函数：

- **回放检测**：把 `corpus/text/**` 归一化后建 8-gram 索引，扫描全部生成物（含 OCR 出来的图像文本），
  命中即失败，白名单仅限公开词表（指标名、单位、标准标签）。2026-09-29 起叙述型文档（科室键值对、超声所见、
  总检）本来就是公共短语的序列，规则放宽为：命中的窗口可由**至多三个连续**的公共词条拼成（开头结尾可切在词中，
  中间必须整词）；带槽位的叙述模板按 spec 声明的槽值展开、在未声明的槽处切开；生成物里的机器标识符
  （厂商字段名、场景名、文档种类）也要在 `spec/vocab.json` 里声明过。
- **PII 谓词**（重写，不复用）：身份证号、手机号、就诊号/条码、`姓名[:：]`、地址、机构名 ——
  且机构名要求**属于虚构池**（白名单，不是黑名单）。
- **spec 溯源检查**：任何无 `source` 标签的字符串 → 失败。
- **距离检查（DCR 类）**：生成行与真实行在 (指标, 值) 上的精确撞值率，与"按取值粒度计算的偶然撞值率"
  比对。**只作 sanity check**——《DCR Delusion》说得清楚，它证明不了隐私，但它能抓到管线接错。
- **外发闸**：任何走网络的路径（若日后再引入 LLM 辅助）只发固定公开结构词表的交集。

### 4.4 临床审计（与生成器独立）

字段级（值在生理可能域内）、跨字段（恒等式：BMI / Friedewald / MCHC / TP=ALB+GLB / 分类合计 100 /
绝对值=WBC×%）、时序（同一人相邻两次的变化幅度超过 RCV 时必须有事件解释）、
人口学（性别专属项目、年龄专属参考区间）。生成器用机理算，审计用**恒等式反查**，两边不共用代码。

### 4.5 仓库卫生（已落地，2026-09-22）

这个仓库要开源，而工作目录里有真实患者文档。三件事已经做完：

1. **`.gitignore` 改成白名单式**：默认忽略根目录下的一切，只放行 `generator/` `harness/`
   `spec/` `tests/` `docs/` `scripts/` 与几份 md。新丢进来的目录**默认进不了 git** ——
   忘记加白名单只会让新代码提交不上，不会让病历上云。黑名单追不上真实数据的长相，
   这一点在这个项目里已经被证明过。
2. **`.githooks/pre-commit` 挡"绕过"**：`git add -f` 能无视 .gitignore，钩子不能。四条规则：
   隐私目录路径、文档与图像扩展名、>1MB 的文件、内容命中 PII 谓词。谓词故意写宽，
   豁免必须显式写在那一行里（`privacy-gate:ok`），而不是把谓词放宽 ——
   放宽是无声的、对所有文件生效的。装法：`git config core.hooksPath .githooks`。
3. **提交历史只含白名单路径**：发布前用 `git fsck --unreachable` 与 `git count-objects` 确认对象库里没有不可达的大对象；
   往仓库里 `git add` 任何批量数据之前要清楚 reset 不等于删除。

## 5. 验收标准（可测量，不是"看起来对"）

| 项 | 标准 | 怎么测 |
|---|---|---|
| 隐私 | 回放检测 0 命中；PII 谓词 0 命中；spec 溯源 100% | `audit/privacy.py`，非零退出 |
| 临床一致性 | 恒等式违反 0；性别冲突 0；RCV 超限且无事件解释 0 | `audit/clinical.py` |
| 版式多样性 | 版式指纹不同比例落在真实值 ± 0.05 内（真实值见 NUMBERS.md，**两边用同一个 `audit/fingerprint.py`**） | `audit/fidelity.py` |
| 形态保真 | column_sets / 参考值方言 / 单位风格 / 标记方言 四族对真实分布的 JS 散度 < 0.15 | 同上 |
| 规模分布 | 每文档 readings 分布对真实直方图 KS 检验 p > 0.05 | 同上 |
| 词表可达 | ≥90% 打印名可被 `mirobody.engine.resolve` 解析；另留 ~10% 刻意不可解析的 frontier 项（考察弃权而非乱猜） | `harness/resolve_coverage.py`（离线、不花钱） |
| 难度单调 | 提取召回 T0 > T2 > T3 > T4；若不单调说明分层没测到东西 | 用 `harness/score.py` 按 `tier` 分组即可；专门的脚本未写 |
| 陷阱密度 | 每份文档陷阱条数分布对实测（**剔除脱敏痕迹后** p50=4/p75=6/p95=8/9.3% 为零）KS 检验 p > 0.05；主榜单无文档超过 p95=8 | `audit/fidelity.py` |
| 版式长尾 | 指纹重复形状复现"重头+长尾"：**按指纹算**与**按文档算**的单次占比都落在真实值 ± 5 个点内（真实值见 NUMBERS.md），且存在 2 个占比 5–10% 的大家族 | 同上。两个分母都要写死——第一版只写"≥75% 的指纹只出现一次"，按指纹算这个阈值松到没有约束力 |
| 采样器值域 | 实测 513 种指纹，采样器每一种都造得出；造不出的要指出缺了哪一维 | **未实现**：目前只有 `audit/fidelity.py` 报告指纹多样性，没有逐指纹的覆盖测试 |
| 可读性下界 | 每条真值行在注入陷阱后仍可读；不可读的行必须已转入"必须弃权"集合，不在召回分母里 | `audit/readability.py` + 抽样人工复核 |
| 确定性 | 同 seed 两次生成逐字节一致 | `tests/test_render.py::test_same_seed_is_byte_identical`、`tests/test_generator.py` |
| 不可过拟合 | 换 seed 即得未见过的一批；评分用"封存 seed"，开发用"开放 seed" | 约定 + CI 检查 |

关于"够不够多"：500 份分 7 层，每层并不均分——OCR 路径要占六成，T0/T1/T5 大约各 65 份。
在 n=65–150、召回 0.8 时，95% 置信半宽是 **±6–10 个百分点**；只有召回到 0.9 以上才收窄到 ±5–7。
（第一版写的是 ±4–6，那是按召回 0.9、n=150 算的，当成通用值就偏乐观了。）
所以这套语料够判断"这次改动让 T3 掉了 10 个点"，**不够**判断 2–3 个点的差异。
要测更细的差异，要么加量，要么在同一批文件上做配对比较（同文件前后对比的方差小得多）。

5. `harness/agent_qa.py`（可选，末期）：用注入事件生成的归因问答集考 agent，答案可判定。

### 6.1 与 ESL-Bench 组合（这是本项目最大的外部价值）

HolyEval（ESL-Bench 的评测框架）里的 ESL-Bench（arXiv:2604.02834，HF `healthmemoryarena/ESL-Bench`）
是本团队的工作：100 个合成用户、10000 条查询、5 个维度（`direct` / `single_hop` / `multi_hop` /
`multi_hop_temporal` / `attribution`）、真值来自生成过程。

**ESL-Bench 缺的正是这一环**：它的用户数据是**已经在库里的结构化记录**——
`benchmark/data/eslbench/.data/<user>/user.duckdb` + `*_timeline.json`。
真实世界里这些数据不是这样到达的，它们是**一堆版式各异、质量参差的文件**。
文档边界上丢掉了多少，ESL-Bench 测不到，现有的文档抽取基准（DocILE/DTBench）又只测到字段 F1 为止。

组合方式（工程上很轻）：

1. **共用虚拟人**。不另造 60 个人，而是取 ESL-Bench 的用户与其 `timeline.json`，
   把同一条事件时间线渲染成文件。同一个 `user113@demo`，两种到达方式。
2. **产出 ESL-Bench 原生格式的题目**。我们的问答集直接按它的 BenchItem schema 出
   （`id / user.strict_inputs / target_overrides / eval.{evaluator: kg_qa, expected_value, key_points,
   difficulty, source_data} / tags`），HolyEval 一行代码不用改就能跑。
3. **得到一个干净的消融**：同一批题、同一个 agent，
   *(a)* 结构化数据直接入库 → 分数；*(b)* 先上传 N 份文件、由产线提取入库 → 分数。
   **差值 = 文档边界的代价**，并且因为 manifest 里有逐份的陷阱清单与版式指纹，
   这个差值可以拆到"哪一类版式现象吃掉了几个点"。


## 7. 阶段与顺序

两道闸门全绿：

| 检查 | 结果 |
|---|---|

| `audit/privacy.py` | **0 回放命中 · 0 PII**（spec + 产物一起扫） |

新增 `spec/cohort.json`：队列设计（8 个原型的患病率配比、6 个干预剧本的药效幅度与起效时间、
5 个随机事件、16 套检验医嘱）从 Python 里搬进 spec，理由有二——
它是可被质疑的**临床主张**（"他汀让 LDL 降 38%、4–6 周起效"），该让人指着看；
而且这些名字会出现在产物里，不声明成公共词汇的话隐私闸门会（正确地）把它们当成来历不明的串。

**跑起来之后被抓出的五个真问题**，其中三个在生成器、两个在审计自己：

1. **红细胞指数的因果方向搞反了**（生成器）。我把血红蛋白与压积当独立变量各自抽样，
   于是 MCHC 落在 300–424（真实 316–354），审计判出"活人不可能"。
   正确的独立变量是**红细胞计数、MCV、MCH**，血红蛋白与压积是它们的乘积。
   进一步地，MCH 的个体基线也不独立：MCHC 的 CVG 只有 2.8%，所以潜变量取 MCV 与 MCHC，
   MCH 由二者决定——这样三个公开的 CVG 才互相自洽。
2. **高变异项目要用对数正态**（生成器）。直接胆红素 CVI 36.8%，加性模型
   `base × (1 + 0.37ε)` 在 ε=−2.6 时给出 0.04 倍基线，一个趋近于零的胆红素。
   生物学量是非负右偏的，乘性噪声才是它的形状。
3. **RCV 逐对报错是把统计尾巴当缺陷**（审计）。RCV 是差值的 95% 界，按定义就该有约 5%
   的相邻对超出它——第一版因此在 601 份记录上报了 586 条。改成：逐对只抓超过 3×RCV 的，
   总体看超出率是否落在 5% 附近。
4. **RCV 要在对数尺度上比**（审计）。`(新−旧)/旧` 在旧值偏小时会炸：
   直接胆红素 0.9→4.6 算出 411%，而 4.6→0.9 只有 80%——同一对数据换个顺序换一个结论。
5. **计算量不能用直接测定法的 CVI 去卡**（审计）。Friedewald 算出的 LDL 继承三次测量的
   传播方差，必然大于 LDL 自己的 CVI；派生指标已排除在 RCV 检查之外。

另外，隐私闸门在这一轮也抓到自己的一个 bug：`.jsonl` 走的是"整文件 json.loads"，
必然失败后退回按行扫原文，于是键名与值被拼在一起（`"start_date": "2026-04-…"` →
`startdate202604…`），报出 44 条并不存在的"逐字搬运"。已改为逐行解析。

**还没做的**：纵向序列目前是围绕设定点的独立抽样，没有慢漂移的自相关。
短间隔超 RCV 的实测比例 9.6%（理论 5%），差额来自趋势项与干预期内的复查，
落在验收带 [1%, 15%] 内。要做 ESL-Bench 那种 Trend 类问题时，建议再加一层 OU 过程的慢漂移。


### 7.3 临床审计的三层（2026-09-23）

| 层 | 是什么 | 拦不拦 |
|---|---|---|
| ① 确定性规则 `audit/clinical.py` | 12 条恒等式 · 生理硬边界（**带完备性测试**）· 人口学 · 标记一致 · RCV 超出率 · **诊断与值互相解释得通** | **拦**，非零退出 |
| ② 多模型交叉标注 `audit/llm_panel.py` | 6 条评分表，多个模型独立会话各打一遍，报均分**与分歧** | 不拦，只排序 |
| ③ 人工校样 `harness/review/` | 单文件离线前端：逐人逐次看，判定 + 备注，导出 `decisions.json` | 人说了算 |

②③ 的设计依据是 MITRE 在 Synthea LLM 工作里的实测（arXiv:2507.21123 表 1）：
同一模块同一评分表，GPT 跑 5 次标准差 18.4、Claude 1.5——**评审模型之间的差异
比被评审对象之间的差异还大**。他们据此选了方差最小的当评审；我们不选，都问，
然后把分歧本身当信号：一致说有问题 → 真有问题；分歧大 → 案例本身模糊，同样要人看。

面板**外发前逐条断言 `synthetic: true`**，有一条不是就整体拒绝，不做"跳过继续"。

#### 关于 ESL-Bench：三条我先前说错了，已核实更正

在把"临床一致性审计"说成对方的缺口之前，应当先读论文和数据。读完之后：

1. ~~"ESL-Bench 的指标值是 LLM 生成的"~~ —— **错**。论文摘要写明是
   *algorithmic simulation with hard physiological bounds*，事件核是 sigmoid 起效 +
   指数衰减；LLM 只负责叙事规划、事件决策与效应参数（β、τ）。
2. ~~"它没有临床一致性审计"~~ —— **错**。它有三级验证（临床专家审事件模板、
   人群边际分布对照公开常模、逐指标 conformance 审计），每个用户导出一份
   audit 报告（conformance / completeness / plausibility），还有硬边界 + **斜率限制**
   + 投影，以及按指标类型选 identity/log/logit 变换。**斜率限制我们没有**。
3. ~~"user5300 的 BMI 半年从 29.44 掉到 24.32，疑似无解释"~~ —— **错**。
   时间线里 2025-11-27 有一条 267 天的事件"悄悄开始每周一次注射用药"（GLP-1），
   后面跟着皮带打新孔、买小一号工装裤、婚戒变松、防护服袖口要收——解释得比我细。

**实测复核**：他们公开数据里的恒等式是成立的——MCV 6/6 精确、MCHC 6/6 精确、
白细胞分类百分比 6 次都恰好 100.00。我原以为的"跨字段恒等式缺口"不存在。

唯一站得住的一条（20 个用户实测）：**值连续达到诊断标准 7 次，其中 2 次本人
慢病列表里没有对应诊断**（user5300 与 user5319，都是血压连续三次 ≥140/90 而
无高血压诊断）。这与他们自上而下的管线一致——画像 → 事件 → 数值，数值漂进
诊断区间不会回流到画像。真实世界里未诊断的高血压极常见，所以这未必是缺陷；
但对一个要考归因的基准来说值得显式决定。我们这边补了回流（`manifest._conditions_of`）。

#### 跑起来之后抓到的四个自家缺陷

1. **腰围 44.2 cm 配 104 kg**。参考区间写成 `range_sex (0,90)`，取中点得 45 cm——
   那个 0 是"无下限"的占位符，不是真下限。改为由 BMI 线性派生。
2. **硬边界表不完备是静默的**。腰围当时不在 `HARD_LIMITS` 里，所以边界检查一声不吭。
   补了完备性测试（每个定量指标要么有边界，要么在豁免表里写明理由），
   补全的同时当场抓出**间接胆红素 −2.1**——直接胆红素是总胆红素的组分，不能独立抽。
3. **MCHC 仍会飘到 403**。红细胞指数的独立变量第三次调整：定为 RBC / MCV / **MCHC**，
   MCH = MCHC×MCV。这样印出来的 MCHC 波动就是它自己的 CVI（1.7%），
   而不是两个独立噪声之比。
4. **RCV 的三处误用**（逐对报错、用相对差而非对数比、拿直接测定法的 CVI 卡计算量）——
   见 §7.2。

## 8. 必须带进新实现的旧教训（来自 2026-08 的早期实现，都踩过）

1. **审计与过滤器必须思路不同**，否则只确认自己的盲区（`panels.json` 里躺过一个真实医生姓名）。
2. **外发一律白名单**，黑名单追不上真实文档的字段名。
3. **"数字脱敏了"不等于安全**：叙述、临床诊断、就诊元信息、病史问卷整行丢弃。
4. **决定清理是否可逆的是判据是否留存，不是字节是否留存**。→ 生成器 + seed 就是判据，
   所以 `out/` 可以随时删，`spec/` 与 seed 不能。
5. **不要为了让分布数字好看去调采样器**（旧 `column_sets` 保真度 0.326 的根因在列头识别，不在采样器）。
6. **算不出的可信度就不要声称**（旧 `4_unlikely` 分层名诱导批量否决，实际 77% 是真报告）。
7. 位置解包在形状变化时不报错、只给错答案；一个决策只能有一处实现。

临床一致性**不是**我们的贡献（ESL-Bench 已有三级验证，公开数据恒等式成立）；
**不能**说首个中文医疗报告抽取基准（MedRepBench，1,925 张真实图像，五字段相同）；
E2 的真实锚点改用公开的 MedRepBench，私有语料只报 ρ。

**这一轮抓出的四个真问题**：

1. **MuPDF Story 跨页时会静默丢内容**。先是 `td { width: 22% }` 让一本报告书从腹部超声到碳13呼气试验整段消失；

   触发条件与分页位置有关，去掉 padding-top、换页幅都只能修好一部分文件。现在的对策是 `render/pdf.py` 的
   `_flow_verified`：每个顶层块单独一个 Story 依次放置；排完立刻核对每个块的文字都在纸上，丢了就把那个块
   强制翻页重排，还丢就把长表拆成几张带表头的小表，16 次仍丢才报错。全语料文本层复核 39,887 行 0 丢失。
   （列宽仍只能用 `width` 属性给，CSS 里的 td 宽度一律不要写。）
2. **纵向审计把量化噪声当跳变**：嗜碱性粒细胞 0.1 → 0.5 的对数比 1.6 被判"无事件解释"，其实 0.1 的真值在 0.05–0.15 之间。

3. **起效中的事件也是解释**：他汀 35 天起效、补铁 90 天起效，事件开始在上次就诊之前、效应落在这一段里，
   `events_since_previous` 第一版只收"这段里开始的"，漏掉了它们。
